## 2. 핵심 요약

Book·Argo CD 자체·Prometheus·Grafana·Blackbox를 Git의 Application 선언으로 관리함. 최초 설치·실습 Secret 준비를 제외한 정상 배포는 Argo 동기화 경로로 통일함. 관측 4단계는 사용자 선택에 따라 지표·HTTP 가용성 관측과 자동 실패·복구 검증을 완료하며 Loki·OpenTelemetry·Tempo는 후속 설계로 둠.

## 3. 상세 내용

### 3.1 관리 주체

| 대상 | 관리 주체 | 비고 |
|---|---|---|
| 서비스 선언·namespace | v2-root Application | App-of-Apps, 관리자 전용 |
| Argo CD·Redis·CRD·RBAC | argocd-self Application | 기존 Helm release 기록 보존, 반복 upgrade 차단 |
| Book 개발·검증 | book-dev / book-verify | 기존 데이터/PVC 보존 |
| Prometheus·kube-state-metrics | prometheus Application | 고정 chart·values |
| Grafana·대시보드·datasource | grafana Application | 기존 Secret 참조, Git에 비밀번호 없음 |
| Blackbox·관측 자원 정책 | blackbox Application | HTTP /ready probe, 먼저 동기화 |
| k3d·Docker registry·K3s DNS/스토리지/metrics-server | 환경 부트스트랩 | 사용자 확인한 서비스 관리 범위의 예외 |
| 최초 Argo 설치·자격 증명·root 진입점 | 최소 bootstrap | 이후 root/self가 자원 인수 |

정상 배포는 수동 sync임. 자동 prune·cascade finalizer를 사용하지 않아 Application 삭제가 샘플 PVC 삭제로 이어지지 않음. Book 장애 실습 중 자동 원복과 충돌하지 않도록 자동 sync도 사용하지 않음. Root는 AppProject를 생성할 수 있고 self는 CRD/RBAC를 관리하므로 플랫폼 관리자 권한 경계임. Book 프로젝트와 분리하고 root 렌더의 이름·종류·소유 및 기존 자원 소유를 검사함. Git 쓰기 권한을 일반 실습 사용자에게 확대하지 않음.

### 3.2 버전·자원·수집 범위

| 항목 | 설정 | 비고 |
|---|---|---|
| Argo CD | 기존 chart10.10.5 / v3.5.5 | vendored 원본 checksum 검증 |
| Prometheus | chart29.37.0 / v3.15.0 | retention6h, size512MB, PVC2Gi |
| Grafana | chart14.0.1 / 13.2.4 | PVC1Gi, dashboard UID v2-platform-lab |
| Blackbox | v0.29.0 + digest 고정 | HTTP200 성공, timeout4s |
| 관측 workload 상한 합계 | 메모리1664MiB·CPU1.95 cores | config reload·KSM 포함, 실측 사용량과 구분 |
| 스케줄링 | Prometheus·Grafana worker1 고정 | 로컬 PVC 제약, 물리 HA 아님 |
| 노드 지표 | CA 검증한 kubelet HTTPS10250 직접 수집 | nodes/metrics GET, nodes/proxy 권한 없음 |
| 상태 지표 | kube-state-metrics·Argo metrics | Secret 조회 권한 없음 |
| Book 관측 | 환경별 probe_success·probe_duration_seconds | 사용자 요청 RPS/앱 내부 latency 계측 아님 |
| 알림 | V2BookUnavailable for30s | Prometheus 내부 firing, 외부 알림 수신 검증 아님 |

Chart 배포물은 `platforms/argocd/chart/charts/`, `platforms/observability/*/chart/charts/`에 보관함. 공급자 index checksum과 비교한 lock이 저장되며 CI가 파일 checksum·렌더·권한을 검사함.

### 3.3 실행 절차

```sh
# 최초 환경은 로컬 실습 가이드에 따라 도구·k3d·이미지를 먼저 준비함.
python3 tools/lab.py argocd
python3 tools/lab.py credentials
# 사용할 SHA의 명세를 GitHub에 push한 뒤 실행함.
python3 tools/lab.py gitops --revision <40자리-커밋-SHA>
python3 tools/lab.py seed
python3 tools/lab.py serve
```

`argocd`는 기존 server가 있으면 Helm upgrade를 실행하지 않음. 새 환경에만 bootstrap chart를 설치하고 최초 Argo/Redis Secret을 생성함. self chart는 Secret·init Job을 렌더하지 않아 관리자 비밀번호·TLS·Redis 인증을 보존함. `deploy`도 직접 Kustomize apply 대신 Book 두 Application을 sync함. `gitops`는 root→self→Blackbox→Prometheus→Grafana→Book 순서로 실행함.

root sync는 지정 SHA로 checkout한 상태 및 platforms 미커밋 변경 부재를 요구함. 다른 버전의 root로 되돌릴 때는 해당 검토 커밋으로 checkout 후 실행함. 일반 서비스 변경도 PR·CI·독립 검토를 거쳐 같은 Git SHA를 동기화함.

| 화면 | 주소 | 로그인·비고 |
|---|---|---|
| Book 개발/검증 | http://localhost:8080 / http://localhost:8081 | 기존 실습 비밀번호 유지 |
| Argo CD | https://localhost:8082 | 기존 admin 비밀번호 유지 |
| Grafana | http://localhost:8083/d/v2-platform-lab | admin / .local/grafana-password |
| Prometheus | http://localhost:8084 | V2 loopback, 외부 공개 없음 |

포워딩은 실행 터미널을 유지해야 함. Pod 재배포 후 연결이 종료되면 serve를 재실행함. Grafana의 V2 Lab 폴더 대시보드는 Git에서 provisioning하며 UI 편집은 기본 비활성임.

### 3.4 복구와 실습

정상 원복은 Git revert와 Argo sync로 수행함. Argo 자체가 동작하지 않으면 같은 검토 커밋의 chart·values로 최소 복구할 수 있음.

```sh
python3 tools/lab.py recover --confirm-recovery
python3 tools/lab.py sync argocd --revision <40자리-커밋-SHA>
```

recover는 cluster/context/소유·고정 chart checksum·렌더 kind/name·기존 자원 소유를 검사함. Secret을 렌더하거나 Helm release를 uninstall하지 않음. 서버 측 적용 충돌을 강제로 인수하는 비상 경로이므로 정상 배포에 사용하지 않음. 적용 기록은 `.local/recovery.json`에 남기며 복구 뒤 GitOps 차이를 다시 대조해야 함.

```sh
# 읽기 전용 지표·Grafana·RBAC 실증
python3 tools/verify_observability.py
# verify Book만 readiness 장애→probe0→alert firing→복구를 자동 검사함.
python3 tools/verify_observability.py --run-fault
```

## 5. 확인 필요 사항

- 자동 지표 검증과 사용자의 직접 진단 실습을 구분함.
- 백업 복원·물리 HA·운영 N100 배포·외부 알림 전달은 이번 검증 대상이 아님.
- 노드별 Pod 메모리 합계는 물리 맥북 전체 메모리 사용량이 아님.
- Loki·OpenTelemetry·Tempo 및 Book 네이티브 앱 계측은 미구현임.
- 비상 복구 경로와 fresh bootstrap 렌더를 실제 전환·기존 데이터 보존 증거와 구분해 기록함.
