## 2. 핵심 요약

V1은 실제 서비스 운영·유지보수를 계속하고 V2는 별도 맥북 실습 환경으로 관리함. 고정 V1 소스의 Portal·Book·YouTube를 재사용하고 GitOps·관측·보안·별도 PostgreSQL 백업 복원을 구성함. 세부 비교는 [V1 대비 V2 구축 정리](20261022_V1대비_V2_구축정리.md)에 기록함. 현재는 승인된 관측·배포 준비 고도화 및 안정화 검증을 우선하며 직접 학습은 이후 재개하고 폐쇄망은 보류함.

## 4. 검토 결과

- 사용자 설계 확인 및 진행 승인에 따라 0~3단계 명세·CLI·정적 CI·실습 도구를 구현함.
- 문서의 링크·차이·비밀값 및 N100 제외 경계를 자기 검증함. 초기 문서 작업으로 하위 에이전트 미사용함.
- 기능·CI/CD·보안 구현 시 AGENTS.md의 독립·전문 검토를 적용함.

## 5. 확인 필요 사항

- 맥북 ARM64·32GiB·논리CPU10개·디스크 약328GiB 여유 확인. OrbStack 시작 및 Docker 엔진 약16GiB 인식 확인. k3d·kubectl은 저장소 전용 경로에 설치함.
- V1 고정 커밋 Book 소스만 추출하여 별도 ARM64 실습 이미지를 빌드하고 V2 loopback registry에 저장함. 비공개 V2 Git 접근용 read-only deploy key는 사용자 명시 승인 후 별도로 등록함.
- k3d server 1개·worker 2개는 스케줄링 연습 후보이며 제어면 HA가 아님. server 3개 HA는 별도 실습으로 계획함. 동일 물리 호스트의 실습을 물리 HA로 표현하지 않음.
- 노드 로컬 PVC의 재스케줄링 제약과 백업 복원을 구분함. namespace 분리를 별도 클러스터나 물리 격리로 표현하지 않음.
- 폐쇄망은 이미지뿐 아니라 설치 바이너리·패키지·chart·Git·인증·서명 검증 자료의 의존성을 포함함.
- CPU LLM 실습을 GPU 운영 경험으로 표현하지 않음. Terraform은 실제 관리할 인프라 대상을 정한 뒤 사용함.

## 6. 후속 조치

0~6단계 구현·관련 독립 검토·CI·병합·맥북 main 반영과 보존 검증을 수행함. 최근 main 검증에서 Argo18개 Synced/Healthy와 Prometheus24개 대상을 확인함. 단계별 수치와 범위는 [구축 정리](20261022_V1대비_V2_구축정리.md), [요청 추적](20261022_V2_요청추적_검증기록.md), [보안](20261022_V2_보안강화_검증기록.md), [데이터 복원](20261022_V2_데이터백업복구_검증기록.md)에 구분함.

후속 격리 실습에서 DB 연결503→정상200, 최신5행 백업의 빈 임시DB 복원·원본5행/기존복원4행 보존·임시 자원 정리를 확인함. 이는 에이전트 실행이며 사용자 직접 진단 경험과 구분함. 사용자는 정상 상태·Pod·로그·이벤트·DB 조회 명령부터 직접 따라 하는 단계임. 폐쇄망은 사용자 요청으로 보류함. SBOM·서명 검증은 미구현이며 별도 범위 확인 전 착수하지 않음.

사용자 승인에 따라 메모 API의 공개 `/version` 경로를 추가하는 배포 실습을 완료함. 코드·테스트 → 로컬 ARM64 이미지 빌드·등록 → digest 및 정책 갱신 → PR·CI·병합 → Argo 수동 Sync → 버전·데이터 보존 확인 순서로 수행함. PR #10 병합 main f46d21dc에서 전체121개 테스트·독립 검토·Argo18개·지표24개·원본5행/복구4행 보존을 확인함. 실행 결과와 직접 확인 방법은 [메모 API 배포 실습](20261022_V2_메모API_배포실습.md)에 기록함. N100 이전·폐쇄망 작업은 포함하지 않음.

직접 실습은 증상만 보고 사용자가 원인을 조사하는 방식과 자동 회귀 검증을 구분함. 결과에는 증상→조사→근거→복구→재발 방지와 실행 원본을 남김.

## 8. 서비스 확장

사용자의 두 서비스 전체 연결 요청에 따라 Portal·YouTube를 기존 Book과 같은 GitOps 방식으로 추가함. V1의 crawler·HomeOps executor·system-agent·car-care와 운영 데이터는 포함하지 않음. V2 이미지는 고정 V1 앱 소스만 추출하고 주소·쿠키 격리 패치를 적용함. 단계별 증거는 서비스 통합 검증 기록에서 관리함.

6단계 진행 상태는 [데이터·백업·복구 검증 기록](20261022_V2_데이터백업복구_검증기록.md)에 구분함. 실제4행복원·기존37개/신규24개자원보존PASS, PR#7병합후main cb442805d15ce70ce64d54c21985ac595c7a89f3의전체18개Argo·24targets·localhost재검증PASS. 현재후속조치는사용자직접운영실습임. 폐쇄망작업은보류하고기타공급망항목은별도범위확인전착수하지않음.
