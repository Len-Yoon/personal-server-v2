# Personal Server V2 로컬 실습 운영 가이드

## 1. 문서 정보

| 항목 | 내용 | 비고 |
|---|---|---|
| 작성일 | 2026-10-21 | Asia/Seoul |
| 목적 | 승인된 0~3단계 로컬 환경 재생성·접속·진단·복구 절차 제공 | 운영 경험과 구분 |
| 기준 자료 | 저장소 명세·tools/lab.py·공식 배포 도구 | 실행 결과는 검증 기록 참조 |
| 실행 범위 | macOS ARM64·OrbStack·V2 전용 k3d | N100·V1 운영 변경 제외 |

## 2. 핵심 요약

V1 앱 소스는 V1에서 관리하고 V2는 플랫폼 명세·실습 도구를 관리함. Book 소스의 고정 Git 커밋만 추출하여 ARM64 이미지를 빌드함. 미추적 파일·실제 DB·.env·운영 자격 증명을 복사하지 않음. V2 이미지 digest를 Git에 고정하고 별도 loopback registry에서 공급함.

| 구성 | 역할 | 비고 |
|---|---|---|
| OrbStack | 로컬 Docker 런타임 | 다른 로컬 작업과 엔진 공유 |
| ps-v2 | k3d server 1·worker 2 | 같은 물리 맥북, 물리 HA 아님 |
| v2-dev / v2-verify | 환경별 Book·PVC·실습 비밀번호 | namespace는 물리 격리 아님 |
| Kustomize | Book base·환경 overlay·이미지 digest | PVC Prune=false |
| Helm | 최초 Argo bootstrap·chart 렌더 | 정상 갱신은 argocd-self Application |
| Argo CD | root/self·Book·관측 서비스 수동 동기화 | 자동 sync·prune 비활성 |

초기 노드 메모리 상한은 server 2GiB·worker 각 3GiB임. registry 256MiB를 추가함. 합계가 Docker 엔진 전체 메모리 한도를 뜻하지 않으며 실제 사용량·macOS 메모리 압박을 확인해 조정함. CPU 6개·디스크 40GiB는 계획 예산이며 현재 별도 VM 상한으로 강제하지 않음. 도구 버전과 배포물 checksum은 `dependencies.json`에 고정함.

## 3. 상세 내용

### 3.1 설치·재생성

필요 도구는 Python 3.11 이상, Git, Docker CLI·OrbStack, Helm임. bootstrap은 k3d·kubectl과 Argo chart를 저장소 내부에 설치하며 시스템 도구를 대체하지 않음.

```sh
cd /Users/len/PycharmProjects/personal-server-v2
python3 tools/bootstrap.py
orbctl start
python3 tools/lab.py doctor
python3 tools/lab.py up
python3 tools/lab.py build --source /Users/len/PycharmProjects/personal-server
# 이미지 digest 변경을 검토·커밋·push한 뒤 아래 명령에 해당 SHA를 사용함.
python3 tools/lab.py argocd
python3 tools/lab.py credentials
python3 tools/lab.py gitops --revision <40자리-커밋-SHA>
python3 tools/lab.py seed
python3 tools/lab.py check
```

Book 고정 source 커밋은 `23572de06038341fc2ed11714cccde04e9967080`임. 해당 커밋이 있는 로컬 V1 Git 저장소를 읽기 전용 입력으로 사용함. `git archive`의 `book-memo/` 소스만 빌드 context에 추출함. V1 저장소 파일을 수정하지 않음. 추출본·이미지 provenance는 `.local/`에 보관함. 새 빌드의 전이 Python 의존성은 V1 requirements의 제한을 따르므로 바이트 단위 동일 이미지 재빌드는 보장하지 않음. 빌드마다 생성된 정확한 digest를 overlay에 기록하고 검증·PR로 갱신함.

개발·검증 쓰기 비밀번호는 새로 생성하여 `.local/dev-password`, `.local/verify-password`에 모드 0600으로 저장함. Argo CD ID는 `admin`, 초기 비밀번호는 `.local/argocd-password`에 저장함. 파일을 로컬 편집기로 열어 확인하며 화면 캡처·Git·증적에 값을 포함하지 않음. 이 저장소는 private임. 이번 실행에서는 사용자 명시 승인 후 V2 저장소에만 적용되는 읽기 전용 SSH deploy key를 등록함. 개인키는 `.local/argocd-repo-key`에 저장하며 argocd 명령이 stdin으로 V2 repository Secret에 적용함. 새 맥북/새 checkout에서는 별도 전용 키를 생성해 GitHub 저장소 Settings → Deploy keys에 쓰기 권한 없이 등록한 뒤 같은 경로에 보관해야 함. 키를 Git에 복사하거나 V1 Secret을 재사용하지 않음. 클러스터 down 후에도 로컬 키와 GitHub deploy key는 남으므로 실습을 영구 종료할 때는 저장소 Settings에서 해당 키를 회수하고 로컬 개인키를 별도 정리함.

### 3.2 localhost 접속

```sh
python3 tools/lab.py serve
```

| 대상 | 주소 | 비고 |
|---|---|---|
| Book 개발 | http://localhost:8080 | 쓰기 로그인에 dev 비밀번호 사용 |
| Book 검증 | http://localhost:8081 | verify 비밀번호 사용 |
| Argo CD | https://localhost:8082 | 로컬 자체 서명 인증서 안내 발생 가능 |
| Kubernetes API | https://127.0.0.1:6550 | 브라우저 앱 주소 아님 |
| Grafana | http://localhost:8083/d/v2-platform-lab | admin / .local/grafana-password |
| Prometheus | http://localhost:8084 | V2 loopback 지표 조회 |
| 로컬 registry | http://127.0.0.1:5001/v2/ | 실습 전용·인증 없는 loopback endpoint |

`serve`를 실행한 터미널을 유지함. 종료 시 포워딩만 중지되고 데이터·클러스터는 남음. Pod 재생성 뒤 port-forward가 종료되면 `serve`를 다시 실행함. 맥북 재시작 이후 OrbStack·클러스터 실행 상태를 확인하고 다시 연결함. localhost만 공개해도 Docker network 내부 registry와 클러스터 관리자 사이의 강한 보안 격리를 뜻하지 않음.

### 3.3 GitOps 변경·배포·원복

1. overlay 이미지 digest 등 명세 변경 후 정적 검증·독립 검토·PR·CI·병합을 수행함.
2. 아래 명령의 SHA에는 GitHub에 존재하는 40자리 커밋 SHA를 사용함.
3. 수동 변경은 Argo UI에서 OutOfSync로 관찰하고 같은 Git SHA 동기화로 원복함.
4. 실패 명세의 Git 배포 실습에서는 실패 커밋·오류 증상을 보관하고 Git revert 커밋을 작성해 동기화함. 로컬 live 패치·snapshot 복구와 Git revert는 별도 검증으로 기록함.

```sh
python3 tools/lab.py sync dev --revision <40자리-커밋-SHA>
python3 tools/lab.py sync verify --revision <40자리-커밋-SHA>
```

수동 sync 모드이며 병합만으로 로컬 클러스터가 바뀌지 않음. Argo Application이 main을 추적해도 이 도구의 sync는 지정한 SHA로 실행함. 동기화 시 새로운 operation 완료와 Deployment rollout을 확인함. 리소스 삭제는 기본 prune하지 않으며 PVC 삭제를 배포 rollback과 혼동하지 않음.

### 3.4 장애 실습

개발 환경을 보존하고 검증 환경만 실습함. worker 장애는 두 Book이 고정된 worker0을 멈추므로 개발 환경도 일시 중단됨. 별도 실습 시간을 확보함.

```sh
python3 tools/lab.py exercise image
# 조사·증적 기록 후 복구
python3 tools/lab.py restore
python3 tools/lab.py check
```

| fault | 예상 증상 | 조사 근거 | 비고 |
|---|---|---|---|
| image | ImagePullBackOff 또는 ErrImagePull | Pod events·image reference | registry의 존재하지 않는 V2 tag |
| pending | Pending / FailedScheduling | nodeSelector·node labels | 존재하지 않는 V2 label 요구 |
| probe | Running, Ready=false | readiness HTTP 404·events | /ready와 liveness 구분 |
| oom | OOMKilled·재시작 | lastState·restartCount·memory limit | Book container를 제한된 메모리 할당 fixture로 대체 |
| worker | worker0 NotReady·Book 접근 중단 | node condition·Pod·PVC node affinity | 다른 노드 데이터 이동/HA 성공으로 표현하지 않음 |

조사는 반드시 전용 kubeconfig·context를 명시함. 기본 context를 사용하지 않음.

```sh
.tools/bin/kubectl --kubeconfig .local/kubeconfig --context k3d-ps-v2 -n v2-verify get pods -o wide
.tools/bin/kubectl --kubeconfig .local/kubeconfig --context k3d-ps-v2 -n v2-verify describe pod <Pod명>
.tools/bin/kubectl --kubeconfig .local/kubeconfig --context k3d-ps-v2 -n v2-verify logs deployment/book --previous
.tools/bin/kubectl --kubeconfig .local/kubeconfig --context k3d-ps-v2 -n v2-verify get events --sort-by=.lastTimestamp
```

실습 시작 전 cluster UID와 Deployment UID를 포함한 spec snapshot을 `.local/exercise.json`에 보관함. 미복구 실습을 덮어쓰지 않음. restore는 같은 cluster·Deployment만 복구하고 rollout 확인 후 snapshot을 제거함. SQLite의 로컬 PVC는 worker0에 종속됨. worker 재시작 후 데이터 유지 확인은 별도 환경 백업·복원 검증을 대신하지 않음.

직접 실습 기록은 `증상 → 조사 명령 → 원본 근거 → 원인 → 복구 → 데이터 확인 → 재발 방지`로 작성함. 자동 fixture 검증을 사용자의 직접 진단 경험으로 기록하지 않음.

### 3.5 자원 정책 확인

환경별 ResourceQuota·LimitRange로 기본 requests/limits·메모리/CPU 상한·PVC 수·스토리지 요청량을 제한함. 한도를 넘긴 Pod가 admission에서 거부되는 것과 admission을 통과한 Pod가 스케줄링되지 못하는 Pending은 다름. 메모리 fault fixture는 64MiB limit 내에서 256MiB를 할당하므로 호스트 메모리 고갈을 유도하지 않음.

### 3.6 정리·실패 복구

```sh
python3 tools/lab.py down
# up이 도중에 실패하여 완성 state가 없을 때만
python3 tools/lab.py cleanup
```

down은 Book 샘플 DB를 포함한 V2 cluster·registry·연결 볼륨을 삭제함. 비밀번호·빌드 source·cache·실습 증거는 `.local/`에 남음. 전체 Docker prune, 이름 prefix 일괄 삭제, 기본 kubeconfig 수정은 수행하지 않음. 기록된 컨테이너 ID·볼륨 fingerprint·network ID 및 외부 연결 여부를 검사한 뒤 정확한 대상만 삭제함. 실패 생성은 journal과 실행 소유 표식으로 식별함. 다른 자원으로 교체됐거나 타 소유 연결이 있으면 삭제를 거부하고 조사함. 강제 종료가 자원 생성과 journal 기록 사이에 발생한 경우 자동 인수하지 않으며 확인 필요로 남김.

## 5. 확인 필요 사항

- 사용자 직접 장애 진단은 자동 검증과 별개로 수행 필요.
- PostgreSQL·백업/복원·관측 stack·폐쇄망·서명 검증은 후속 단계임.
- V2 registry는 영속 제품 registry가 아니며 down 후 새 이미지 공급이 필요함.
- 로컬 Docker 관리자 권한, Pod 네트워크의 세부 통제는 후속 보안 단계에서 확장함.

## Portal·YouTube 통합 운영

고정 V1 앱 소스만 추출하며 운영 env·DB·Secret은 사용하지 않음. 주소/쿠키 패치는 `tools/v2_source_patch.py`, 이미지와 원본 archive 해시는 `apps/images.lock.json`에 기록됨.

```sh
python3 tools/lab.py build --app portal --source /Users/len/PycharmProjects/personal-server
python3 tools/lab.py build --app youtube --source /Users/len/PycharmProjects/personal-server
python3 tools/lab.py build --app book --source /Users/len/PycharmProjects/personal-server
# 변경을 검토·커밋·push한 뒤 해당 SHA로 root 및 서비스 수동 동기화
python3 tools/lab.py gitops --revision <40자리_SHA>
python3 tools/verify_services.py --restart-samples
python3 tools/lab.py serve
```

Portal 개발8000/검증8090, YouTube 개발8002/검증8092, Book 개발8003 또는8080/검증8081로 접속함. 전체 로그인 정보는 `.local/V2_로그인정보.md`(0600)에 저장됨. Portal의 파일함·관리자·포트폴리오·삭제에는 해당 환경 Portal 비밀번호를 사용함. localhost 쿠키는 포트별로 격리되지 않으므로 V2 이미지에서 개발/검증 쿠키 이름 prefix를 분리함.

Portal은 같은 namespace의 Book·YouTube와 DNS로만 통신함. YouTube는 DNS만 외부 통신을 허용하여 원격 제목 조회는 실패 시 기본 제목을 사용함. 영상 저장 후 메모를 작성할 수 있으며 YouTube 재생 자체는 브라우저의 인터넷 연결에 의존함. HomeOps·시스템 상태·뉴스·운영 백업 연계는 미연결이며 오류/사용 불가 표시가 정상임. 이 상태는 전체 폐쇄망 설치 검증을 뜻하지 않음.

단일 worker에 고정된 로컬 PVC이며 다른 노드로의 데이터 이동·외부 백업 복구·HA는 검증 범위에 포함하지 않음.

## Loki·Alloy 로그 수집

Loki·Alloy는 GitOps 수동 동기화 대상이며 Loki 저장소는 별도 PVC임. Grafana의 Loki 데이터소스(`v2-loki`)와 `V2 Logs` 대시보드를 사용함.

```sh
python3 tools/validate_logging.py
python3 -m unittest discover -s tests -v
# 변경을 검토·커밋·push한 SHA로 root→quota(blackbox)→Loki→Alloy→Prometheus→Grafana 순서 반영
python3 tools/lab.py gitops --revision <40자리_SHA>
python3 tools/lab.py serve
python3 tools/verify_logging.py --restart-loki
```

`--restart-loki`는 수집기 중지·Loki 재생성·과거 합성 로그 조회·수집기 복구를 검증함. Loki PVC는 삭제하지 않으며 UID가 달라진 타 자원은 변경하지 않음. 단일 로컬 저장소의 재시작 보존과 외부 백업 복원은 구분함. 수집기 중단 중에는 로그 지연·손실·중복 가능성이 있으며 무손실 전달은 검증 범위가 아님.

Grafana에서 http://localhost:8083/d/v2-logs 로 이동해 환경·namespace·서비스를 선택함. 앱 문제는 지표 대시보드의 상태와 Pod 로그·events를 함께 확인함. Loki는 별도 localhost 포트를 공개하지 않음. 로그 보존은 24h 설정과 삭제 지연을 따르며 호스트 디스크 사용량의 강제 상한이 아님.

## 요청 추적 확인

- Portal에서 검색: 개발 <http://localhost:8000/?q=V2>, 검증 <http://localhost:8090/?q=V2>.
- Grafana <http://localhost:8083/d/v2-traces/v2-traces>의 환경·서비스를 선택하여 요청을 조회함. trace 상세에서 Portal→Book·YouTube 부모 관계와 구간 시간을 확인함.
- V2 Logs의 `trace_id` 링크로 동일 요청의 Tempo trace를 열 수 있음. health/ready/metrics/static 요청은 추적하지 않음.
- 로그인 정보는 Git 밖 `.local/V2_로그인정보.md`에 저장됨. 접속이 끊기면 저장소에서 `python3 tools/lab.py serve`로 localhost forward를 실행함.
- 자동 연결 검증: `python3 tools/verify_tracing.py`. 실제 이미지의 자동 전송 차단 확인: `python3 tools/verify_tracing.py --check-image-export`. 기존 trace 보존까지 검증: `python3 tools/verify_tracing.py --restart-tempo`. 후자는 Alloy를 잠시 중지하고 Tempo Pod만 재생성한 뒤 복구함. 중단되어 수집기 중지 기록이 남으면 `python3 tools/verify_logging.py --restore-collector`로 동일 UID의 Alloy만 복구함.
- trace는 HTTP 메서드·등록 경로 템플릿·상태·서비스/환경만 저장함. query·헤더·본문·예외 원문은 trace에 저장하지 않음. 단일 로컬 저장소이므로 장기 보관·HA 용도로 사용하지 않음.

## 보안 정책과 진단 계정

- 앱은 전용 SA와 tokenoff, 진단 계정 `v2-diagnostics`는 같은 환경의 pods/events 조회·pods/log 읽기만 허용함. 관리자 kubeconfig의 권한이 줄어드는 것은 아님.
- 보안 정책은 `security` Argo Application으로 관리하며 dev/verify의 Pod·Deployment 생성/수정과 ephemeral subresource를 검사함. tag 이미지·잘못된 SA·토큰 투영·소유 표식 누락 등은 API 단계에서 거부됨.
- `python3 tools/verify_security.py`는 실제 API 권한·허용/차단 패킷·별도 Secret 교체·기존 데이터 보존을 확인함. `--exercise-recovery`는 Binding 한 개를 잠시 Warn/Audit로 전환했다가 Deny로 복원함.
- 중단된 fixture 정리: `python3 tools/verify_security.py --cleanup`. 중단된 Binding 복구: `python3 tools/verify_security.py --restore-binding`. journal의 소유·cluster UID·자원 UID와 맞는 대상만 처리함.
- 기존 비밀번호 파일이 유실되거나 기존 Secret과 다르면 `credentials`는 자동 재발급·덮어쓰기를 거부함. 저장된 로그인 정보와 원래 파일을 확인하여 원인을 해결한 뒤 재실행함. Secret을 지워서 통과시키지 않음.
- `exercise image`는 보안 정책과 호환되는 고정 missing digest를 사용함. 정책 거부와 ImagePullBackOff를 구분하며, 복구는 기존 `restore` 또는 검토한 Git 명세 동기화로 수행함.
- Book 외부 검색용 HTTPS 예외와 Alloy API 통신 예외는 남아 있음. 완전한 폐쇄망·도메인 allowlist·관리자 접근 차단 완료로 표현하지 않음.
