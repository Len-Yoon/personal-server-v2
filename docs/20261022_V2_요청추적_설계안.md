# V2 요청 추적 설계안

## 1. 문서 정보

| 항목 | 내용 | 비고 |
|---|---|---|
| 작성일 | 2026-10-22 | Asia/Seoul |
| 목적 | Portal 통합 검색의 Book·YouTube 호출을 단일 trace로 확인함 | 개발 계획4-3 |
| 기준 | V2 main fba8cc37d898eb3378cd291f99130c1ebe0fd710·원본 앱·공식 문서 | 실행 결과와 설계 구분 |
| 상태 | 사용자 추천안 승인·구현 진행 | 2026-10-22 세 앱 dev/verify 계측 승인 |
| 실행 경계 | 맥북 V2 개발·검증 환경 | N100·V1 운영 변경 제외 |

## 2. 핵심 요약

세 앱의 HTTP 서버와 Portal의 HTTP 클라이언트를 OpenTelemetry로 계측함. 기존 Alloy가 OTLP trace를 받아 단일 Tempo에 전달하고 Grafana가 조회함. HTTP 요청의 시간·상태·서비스 간 부모/자식 관계를 우선 구현하며 SQL·메모 본문·브라우저 사용자 행동 수집은 범위에 포함하지 않음.

사용자가 세 앱 전체 계측 추천 구성을 승인함. 패키지·이미지 버전은 공식 릴리스와 Python3.11/ARM64 호환성을 확인하여 구현 시 고정함.

## 3. 상세 내용

### 3.1 요청 및 수집 흐름

```text
브라우저 → Portal 검색 요청
             ├─ HTTPX → Book 검색 API
             └─ HTTPX → YouTube 검색 API

각 앱의 HTTP span → 기존 Alloy OTLP receiver → Tempo 전용 PVC
각 앱의 trace ID 포함 표준 로그 → 기존 Alloy 로그 수집 → Loki
Grafana: trace 조회 / 로그의 trace ID로 Tempo 이동
```

| 항목 | 추천안 | 비고 |
|---|---|---|
| 앱 계측 | V2 이미지에 명시적인 FastAPI·HTTPX 계측 초기화 추가 | 고정 V1 소스 추출·V2 패치 방식 유지 |
| 적용 환경 | dev/verify 각각 Portal·Book·YouTube, 총6개 앱 인스턴스 | 실제 DB·자격 증명 재사용 없음 |
| 자동 계측 범위 | HTTP 서버·허용한 내부 HTTP 클라이언트만 | SQLite·외부 서비스·무차별 라이브러리 계측 제외 |
| 전파 | W3C trace context를 내부 서비스 호출에 전파 | 동일 trace ID·부모/자식 span 연결 검증 |
| 수집기 | 기존 Alloy에 OTLP/HTTP 수신·배치·메모리 제한 추가 | 별도 collector 중복 설치 없음 |
| 저장소 | Tempo 단일 인스턴스·로컬 PVC2Gi·24h 보존 정책 초안 | 단일 호스트 평가용, 자동 삭제 실측 별도 |
| Grafana | Tempo 데이터소스·trace 조회·Loki trace ID 연결 | 기존 지표·로그 대시보드 보존 |
| 로그 상관관계 | 유효한 trace ID·span ID를 로그 앞부분에 추가 | 마스킹으로 로그 뒷부분이 잘려도 ID 유지 |
| 트래픽 | 준비/생존 점검·metrics·정적 파일 추적 제외 | 실습 요청 중심, bounded batch/queue 적용 |
| Argo | Tempo Application 추가, 앱/Alloy/Grafana 갱신도 GitOps | 기본 수동 sync·기존 소유 검사 유지 |

### 3.2 데이터 보호와 접근

| 경계 | 적용 방침 | 비고 |
|---|---|---|
| trace 속성 | HTTP 메서드·라우트 패턴·상태 코드·고정 서비스/환경 식별자만 허용 | 원본 URL query·검색어·사용자 식별자·DB 문장 제외 |
| 헤더/본문 | Authorization·Cookie·요청/응답 본문 수집하지 않음 | 임의 헤더 자동 수집 비활성 |
| 예외 | 예외 메시지·stacktrace·status description의 임의 문자열 제외 | 오류 유형·상태 위주로 확인 |
| 이중 보호 | 앱 exporter 전송 전 allowlist와 Alloy의 제한된 처리 구성 | 합성 민감값 canary로 미포함 확인 |
| trace ID | 로그 본문에만 기록 | Loki label로 추가하지 않아 stream 증가 방지 |
| OTLP | V2 앱→Alloy, Alloy→Tempo만 허용 | Portal·YouTube의 기존 egress 차단 경계에 명시 예외 추가 |
| Tempo 조회 | Grafana·필요한 관측 Pod만 접근, 외부 포트 공개 없음 | Grafana 관리자 인증 사용 |
| 기존 역할 | 로그 수집 Role의 권한을 추가 확대하지 않음 | trace 수신에 K8s Secret/exec 권한 불필요 |

### 3.3 자원 예산

읽기 전용 확인 시 node 메모리는 worker0 533Mi·worker1 1042Mi·server914Mi임. 한 시점의 사용량이며 최악 부하의 여유를 보장하지 않음.

| 항목 | 현재/설계 | 비고 |
|---|---|---|
| 관측 namespace memory limit 합계 | 현재2816Mi, Tempo512Mi 추가 시3328Mi | quota3Gi→4Gi 조정 필요 |
| Tempo 요청/상한 | memory128/512Mi 초안 | 실제 부하·query·재시작 검증 후 확정 |
| Tempo 배치 노드 | worker0 우선 검토 | worker1 관측 집중 완화, 로컬 PVC 제약 기록 |
| Alloy | 우선 기존256Mi 상한 내 메모리 limiter·bounded batch 설계 | 실제 로그+trace 동시 부하 검증 후 조정 여부 판단 |
| 저장소 요청 | 현재5Gi/8Gi, Tempo2Gi 추가 시7Gi/8Gi | PVC 개수 현재3/6→4/6 |
| 앱 메모리 | 우선 기존 requests/limits 유지, 계측 전후 비교 | SDK 추가 비용은 실측 필요 |

### 3.4 대안 비교

| 선택 | 효과 | 판단·비고 |
|---|---|---|
| 세 앱 HTTP 연계 계측 | 검색1회에 Portal→Book·YouTube 관계와 구간별 시간을 확인 가능 | 추천 |
| Portal 단독 계측 | 초기 변경 범위가 작음 | Book·YouTube 내부 처리까지 연결된 trace는 확인할 수 없음 |
| 범용 무설정 자동 계측 전체 적용 | 초기 실행이 간편함 | 불필요한 SQL·외부 호출·민감 속성 수집 범위가 커져 초기안에서 제외 |

## 5. 확인 필요 사항

- Tempo·OTel 패키지의 정확한 버전·image digest·Python3.11/ARM64 호환성은 구현 전 고정할 필요가 있음.
- 앱→수집기 전송 전 allowlist가 exception event·status description·resource에도 적용되는지 검증 필요함.
- Collector/Tempo 장애 중에도 앱 요청이 정상 응답하고 queue가 제한되는지 확인 필요함.
- 추가 SDK·수집·조회 부하가 기존 Grafana 메모리와 API tail에 미치는 영향 확인 필요함.
- 24h 보존 정책과 시간 경과 삭제·다른 노드 백업 복원은 별도로 구분함.

## 6. 후속 조치와 성공 기준

승인된 범위에서 구현·자기 검증·구현 미참여 전문 검토·PR·CI·병합·main 동기화를 진행함.

| 검증 | 성공 기준 | 비고 |
|---|---|---|
| 서비스 연결 | dev/verify 각각 검색1회에 Portal·Book·YouTube가 동일 trace ID로 연결됨 | 합성 실습 데이터 사용 |
| 로그 연결 | 해당 요청의 로그 trace ID에서 실제 저장된 trace 조회 가능 | 미수집/미샘플 ID와 구분 |
| 데이터 보호 | 합성 토큰·검색어·헤더·본문·임의 예외 문자열이 export/저장 결과에 없음 | 실제 비밀값 사용 없음 |
| 장애 영향 | trace 저장소 중단 중 앱 요청·기존 지표/로그가 유지되고 buffer가 제한됨 | 앱 가용성과 trace 전달 손실 구분 |
| 자원 | 반복 검색·trace 조회 후 OOM/비정상 재시작 없음 | 한정된 실습 부하 결과로 기록 |
| 보존 | Tempo 재생성 후 이전 trace 조회 및 동일 PVC UID 확인 | 재전송과 저장 보존을 분리 |
| 기존 자원 | 기존 앱·Secret·PVC UID/비밀번호 hash·샘플 데이터·로그/지표 유지 | N100/V1 운영 상태 변경 없음 |
