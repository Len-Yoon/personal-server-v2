## 2. 핵심 요약

앱별 전용 ServiceAccount, 제한된 진단 권한, dev/verify 기본 통신 거부와 허용 경로, 내장 VAP/CEL 정책을 구현함. 기존 PSA restricted를 유지하며 앱 명세·최종 Pod의 소유·전용 SA·토큰 차단·이미지 고정·자원을 검사함. Secret 도구는 기존 값을 다시 적용하지 않고 파일·Secret 불일치 시 중단하도록 변경함.

## 5. 확인 필요 사항

- Argo 관리자·관리자 kubeconfig는 신뢰 경계이며 읽기 전용 계정으로 바뀌지 않음.
- Secret API 거부는 Pod 생성 권한자의 Secret 마운트나 호스트 관리자의 접근까지 차단하는 증거가 아님. 진단 Role에는 Pod 생성 권한을 부여하지 않음.
- 표준 NP의 node-local·hostNetwork·DNAT 제한과 공개 HTTPS 예외를 구분함. API 노드 경로는 관찰값으로 기록하며 일반 Pod 간 차단으로 확대하지 않음.
- Book 외부 API가403/429를 반환하면 HTTPS 연결 성공과 도서 API 기능 성공을 별도로 기록함.
- 짧은 유효기간 TokenRequest는 실제 API 인증 검증에만 메모리에서 사용함. 저장·명령행·환경 변수로 전달하지 않음.
- 이미지 digest 고정은 서명/출처 신뢰 증명이 아니며, Secret 저장소 암호화·폐쇄망 설치·서명 검증은 이후 범위임.

## 6. 후속 조치

실제 허용·거부·복구·보존 검증을 완료함. 최종 독립 검토·CI 후 병합하고 main을 수동 동기화함. 실습 정리는 `python3 tools/verify_security.py --cleanup`, 중단된 Binding 복구는 `python3 tools/verify_security.py --restore-binding`으로 동일 소유/UID만 처리함.

## 7. 검증 명령

- 전용 가상환경에서 `python -m unittest discover -s tests -v`
- 최초 audit: `python3 tools/verify_security.py --audit-bootstrap <검토된 SHA>`
- Deny 동기화: `python3 tools/lab.py sync security --revision <검토된 SHA>`
- 실증과 복구: `python3 tools/verify_security.py --exercise-recovery`
- 기존 로그·trace: `python3 tools/verify_logging.py`, `python3 tools/verify_tracing.py`
