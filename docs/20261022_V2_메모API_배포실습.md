# V2 메모 API 코드 변경·GitOps 배포 실습

## 1. 문서 정보

| 항목 | 내용 | 비고 |
|---|---|---|
| 작성일 | 2026-10-22 | Asia/Seoul |
| 목적 | 코드 수정부터 맥북 Kubernetes 배포까지 실제 흐름 확인 | 사용자 직접 실습과 구분 |
| 대상 | V2 notes-api, k3d-ps-v2 / v2-data-dev | N100·V1 제외 |

## 2. 핵심 요약

기존 Pod의 `/version` 404 응답을 확인한 뒤 새 경로를 추가함. 응답은 `{"service":"v2-notes-api","version":"1.1.0"}`으로 고정함. 버전은 앱 릴리스 번호이며 Git SHA나 이미지 digest를 대신하지 않음. 비밀번호·환경변수·호스트 정보는 응답에 포함하지 않음.

## 3. 상세 내용

| 순서 | 수행 내용 | 비고 |
|---:|---|---|
| 1 | apps/notes-api/app.py와 관련 회귀 테스트 변경 | 버전 경로는 인증·DB 없이 읽기 가능 |
| 2 | 전체 테스트 및 독립 검토 | GitHub Actions에서도 자동 검사 |
| 3 | python3 tools/build_data.py | ARM64 빌드·로컬 registry 등록·digest 잠금 |
| 4 | 기능 브랜치 push·PR·검사·main 병합 | CI는 이미지 빌드·배포를 수행하지 않음 |
| 5 | data-policy → data-dev → data-restore 순서 수동 Sync | 복구 API replicas=0 유지 |
| 6 | localhost 버전·readiness 및 데이터 보존 확인 | 기존 메모 삭제·재작성 없음 |

배포 시 저장소 루트에서 병합된 main을 체크아웃하고 아래 순서로 실행함.

```sh
REVISION=$(git rev-parse HEAD)
python3 tools/lab.py sync data-policy --revision "$REVISION"
python3 tools/lab.py sync data-dev --revision "$REVISION"
python3 tools/lab.py sync data-restore --revision "$REVISION"
```

포워딩은 별도 터미널에서 `python3 tools/lab.py serve`로 유지함. Pod 교체로 기존 포워딩이 종료되면 다시 실행함. 브라우저에서 [버전 확인](http://localhost:8086/version), [준비 상태](http://localhost:8086/ready)를 확인함. 메모 조회·변경에는 기존 Bearer 인증이 필요함.

| 실행 결과 | .local/notes-release-result.json | 최종 배포 후 생성, Git에 비밀값·개별 메모 미기록 |

## 5. 확인 필요 사항

- 이 문서 작성 시점에는 최종 CI·병합·배포 결과가 확정되지 않음. 실제 성공 여부는 PR 검사 및 로컬 실행 기록으로 확인 필요함.
- 이미지 정책은 새 digest만 허용하므로 정책 Sync부터 앱 Sync 사이에 이전 이미지의 Pod 재생성이 거부될 수 있음. 세 단계를 연속 수행하며 실패 시 정책 상태와 Pod 이벤트를 확인함.
- 되돌릴 때는 코드·이미지 lock·dev/restore 명세·정책을 함께 이전 상태로 복원한 Git 커밋을 만든 뒤 CI·병합·같은 순서의 Sync를 수행함. DB 복원·PVC 삭제는 포함하지 않음.

## 6. 후속 조치

배포 완료 후 사용자가 `/version`과 `/ready`를 직접 확인함. 다음 단계인 실패 배포·Git revert 실습과 빌드 자동화는 이번 실행 결과와 구분함. 폐쇄망 및 N100 이전은 보류함.
