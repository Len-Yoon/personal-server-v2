## 2. 핵심 요약

OpenTelemetry SDK를 사용한 명시 ASGI·내부 HTTPX 계측을 V2 이미지에 추가함. 자동 라이브러리 계측 대신 HTTP 최소 범위를 구현하여 임의 URL·query·헤더·본문·예외 정보가 전송되지 않도록 함. 각 앱 exporter가 허용 필드로 OTLP protobuf를 새로 구성하며 기존 Alloy가 이를 받아 Tempo에 전달함.

| 검증 | 결과 | 비고 |

| 계측 자기 검증 | 11개 PASS | 실제3HTTP서버·APIRouter/nested·streaming·예외·외부redirect·수집기장애·queue상한 |

| 전체 회귀·CI | 진행 중 | 원본 .local/tracing-tests.log |

역할은 주 담당(root: 이미지·CLI·CI·런타임 검증·문서), 계측 구현(observability), 플랫폼 구현(manifests), 독립 보안·배포 검토(review)로 분리함. 검토자는 구현 파일을 수정하지 않음. 사전 검토에서 발견한 외부 redirect 전파, Uvicorn formatter 인자, FastAPI include_router 경로, CI 의존성 누락은 수정 및 회귀 검증 대상으로 반영함.

## 5. 확인 필요 사항

- 24h 경과 자동 삭제, 다른 노드·다른 호스트의 백업 복원은 미수행임.
- 단일 Tempo/로컬 PVC는 HA가 아니며 SDK·Alloy 재시작이나 queue 초과 시 trace 손실 가능함.
- 기존 로그 마스킹은 고정 키 기반 보조 장치이며 모든 임의 민감 문자열 제거를 보장하지 않음. 이번 개인정보 검증은 trace 전송·저장 경계임.
- 한정된 합성 부하 검증은 장시간 운영 부하·전체 성능 특성을 보장하지 않음.

## 6. 후속 조치

실제 연결·보존·장애 영향·자원을 검증하고 최종 독립 검토·CI 후 병합 및 main 수동 동기화를 수행함. 사용자는 Portal에서 검색 후 Grafana V2 Traces에서 요청 구간을 확인할 수 있음.
