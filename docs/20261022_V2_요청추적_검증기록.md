## 2. 핵심 요약

OpenTelemetry SDK를 사용한 명시 ASGI·내부 HTTPX 계측을 V2 이미지에 추가함. 자동 라이브러리 계측 대신 HTTP 최소 범위를 구현하여 임의 URL·query·헤더·본문·예외 정보가 전송되지 않도록 함. 각 앱 exporter가 허용 필드로 OTLP protobuf를 새로 구성하며 기존 Alloy가 이를 받아 Tempo에 전달함.

역할은 주 담당(root: 이미지·CLI·CI·런타임 검증·문서), 계측 구현(observability), 플랫폼 구현(manifests), 독립 보안·배포 검토(review)로 분리함. 검토자는 구현 파일을 수정하지 않음. 사전 검토에서 발견한 외부 redirect 전파, Uvicorn formatter 인자, FastAPI include_router 경로, CI 의존성 누락을 수정함. 실제 환경에서 native 중간 context로 부모가 끊긴 문제는 요청별 ContextVar와 동시12요청/24client 회귀로 보완함. 추가 수집 카운터 조사로 FastAPI가 lifespan에서 기본 OTLP exporter를 자동 생성하는 우회 경로를 확인하고 생성자5개 옵션과 환경 변수3개로 차단함. 최초 부모 검증 실패와 자동 전송 차단 전 결과는 최종 성공 증거로 합산하지 않음. 전송 전 정보 제거는 exporter 코드/민감값 unit 검사, 실제 이미지 lifespan에서 native0·private1 송신 검사, 실제 저장 trace allowlist 검사를 합쳐 판단함.

실측 대상 앱/플랫폼은 fa6b14f 및 동일 이미지 digest이며, 검증 도구의 SDK `span_processor` 속성 수정과 compile 회귀를 포함함. `python3 tools/verify_tracing.py --check-image-export --restart-tempo`, `python3 tools/validate_logging.py`, 전용 가상환경의 `python -m unittest discover -s tests -v`로 검증함. CI/병합/main 동기화 상태는 PR#5와 병합 후 증적에서 별도로 확인함.

## 5. 확인 필요 사항

- 24h 경과 자동 삭제, 다른 노드·다른 호스트의 백업 복원은 미수행임.
- 단일 Tempo/로컬 PVC는 HA가 아니며 SDK·Alloy 재시작이나 queue 초과 시 trace 손실 가능함.
- 기존 로그 마스킹은 고정 키 기반 보조 장치이며 모든 임의 민감 문자열 제거를 보장하지 않음. 이번 개인정보 검증은 trace 전송·저장 경계임.
- 한정된 합성 부하 검증은 장시간 운영 부하·전체 성능 특성을 보장하지 않음.

## 6. 후속 조치

실제 연결·보존·장애 영향·자원 검증과 최종 독립 검토를 완료함. 최종 CI 후 병합 및 main 수동 동기화를 수행함. 사용자는 Portal에서 검색 후 Grafana V2 Traces에서 요청 구간을 확인할 수 있음.
