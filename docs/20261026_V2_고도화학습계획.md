## 2. 핵심 요약

**현재 우선순위는 메모 API 관측·배포 준비 자동화 고도화 → 안정화 검증 → 사용자 학습 재개임.** 사용자 승인에 따라4주차 관측과6주차 반복 작업 개선을 먼저 구현함. 범위와 검증 결과는 [고도화 검증 기록](20261026_V2_관측배포_고도화검증.md)에 구분함. 학습 재개 시 V2 1주차 정상 상태·요청 추적부터 시작하고 V1 읽기 점검은 별도 범위로 병행 가능함.

이미 구성한 k3d·GitOps·지표·로그·trace·보안·PostgreSQL 백업 복원을 재설치하는 과제가 아님. 직접 진단과 정량적 신뢰성 운영을 우선하고, 목표 공고에 필요한 경우에만 선택 Terraform 실습을 진행함. 기존 에이전트 자동 검증은 사용자 직접 수행 경험으로 바꾸어 기록하지 않음.

관련 기준: [기존 개발 계획](20261021_V2_개발계획.md), [로컬 실습 가이드](20261021_V2_로컬실습_운영가이드.md), [V1 대비 구축 범위](20261022_V1대비_V2_구축정리.md), [V1 계획](https://github.com/Len-Yoon/personal-server/blob/main/docs/20261026_V1_고도화학습계획.md).

## 3. 상세 내용

### 3.1. 학습 재개 후 첫 과제 — V2 1주차

| 순서 | 직접 할 일 | 완료 기준 | 비고 |
|---:|---|---|---|
| 1 | 아래 doctor·status로 기존 환경과 소유 경계를 확인함 | 도구·클러스터 상태와 미복구 실습 유무를 설명함 | 실패하면 초기화·재생성 대신 원인 확인 |
| 2 | 명시 kubeconfig·context로 Pod·Service·Endpoint·PVC·Argo 상태를 조회함 | Ready·Service 선택 대상·Bound·Synced/Healthy의 의미를 구분함 | 기본 context에 의존하지 않음 |
| 3 | 필요하면 serve로 localhost 접속 후 Portal 검색 1건을 수행함 | 검색 결과와 Book·YouTube 요청 관계를 확인함 | serve는 포워딩 프로세스를 시작함 |
| 4 | Grafana 로그·trace에서 같은 요청을 추적하고 흐름도를 작성함 | 요청 ID 연계·부모 관계와 실패 지점을 설명함 | 결과 원문·비밀값 공개 금지 |

기존 환경에서 시작하는 명령임. 이 문서를 저장하면서 실행한 명령이 아님.

```sh
python3 tools/lab.py doctor
python3 tools/lab.py status
.tools/bin/kubectl --kubeconfig .local/kubeconfig --context k3d-ps-v2 -n v2-dev get pods,services,endpoints,pvc
.tools/bin/kubectl --kubeconfig .local/kubeconfig --context k3d-ps-v2 -n argocd get applications
# 기존 환경 확인 후 접속 포워딩이 필요한 경우 실행함.
python3 tools/lab.py serve
```

현재 접속 위치는 README의 localhost 표를 따름. 장애 주입·up/build/sync/restore는 1주차 정상 조회와 별도 동작임. 후속 기록 권장 파일명은 `YYYYMMDD_V2_정상상태점검.md`이며 완료 전 빈 성공 증적을 만들지 않음.

## 4. 검증·실행 경계

- N100 접속·배포·재시작·V1 운영 데이터·PVC·Secret 사용은 제외함. 장애 주입은 명시 V2 context와 소유 표식·대상 UID를 확인한 실습 자원만 대상으로 함.
- worker 장애는 같은 worker의 개발 앱에도 영향을 줄 수 있음. 2주차 첫 실습은 이미지·probe 등 좁은 범위부터 시작하고 영향 범위를 확인함.
- notes-api metrics endpoint 제공과 기존 Prometheus·로그·trace 수집을 구분함. 4주차는 기존 endpoint의 수집 연결부터 구현·검증함.
- 기존 RTO 11.471초는 환경·이미지·빈 DB 준비 시간을 제외한 소형 복원 측정임. 전체 준비·복원 시간을 구간별로 측정하고 같은 맥북 실습을 물리 DR/HA로 표현하지 않음.
- 3주차 배포 복구·4주차 관측·5주차 별도 환경·6주차 자동화는 구체 범위와 성공 기준을 정리한 뒤 진행함. 기능·CI/CD·보안·DB·배포 변경은 AGENTS.md의 독립·전문 검토를 적용함.
- Terraform은 선택 항목임. 관리할 기반 자원과 Argo 앱 자원의 소유 경계를 분리하고 V1 운영 자원을 이전하지 않음. 폐쇄망·SBOM·서명 검증은 별도 후속 범위를 유지함.

## 5. 검토 결과

- 기존 구현·에이전트 자동 검증과 사용자 직접 수행을 구분함. 기존 자동복구·백업을 처음부터 다시 만드는 과제를 추가하지 않음.
- 문서 저장은 실습 완료 또는 향후 기능·운영 변경의 포괄 승인을 뜻하지 않음. 실제 작업은 사용자 요청과 저장소 AGENTS.md의 설계·검증·독립 검토·운영 승인 기준을 적용함.
- 이번 변경은 주 담당 1명이 작성·자기 검수하는 문서 작업임. 실행 코드·CI·배포 설정을 변경하지 않아 하위 에이전트를 사용하지 않음. 독립 검토 완료로 표현하지 않으며 PR·CI 결과는 해당 PR에서 확인함.

## 6. 확인 필요 사항

- 사용자 직접 실습 결과와 최신 실행 상태는 확인 필요함. 과거 테스트·에이전트 실행·문서의 성공 수치를 현재 상태나 사용자 숙련으로 간주하지 않음.
- 회사 경력·연차·클라우드 담당 범위는 확인 필요함. 두 저장소에 구현이 없다는 이유로 전체 경력에서 미경험이라고 단정하지 않음.
- 주 5~7시간·6주 및 선택 2주는 권장 학습 분량임. 달력상 시간이 지났다고 다음 주차로 자동 진급하지 않음.

## 7. 후속 조치와 이어가기

1. 현재는 고도화·안정화 검증을 먼저 진행함. 완료 후에도 사용자의 직접1주차는 자동 완료 처리하지 않으며 학습 재개 요청 시 아래 순서를 적용함.
2. 사용자가 “내가 뭐 해야 해?”, “다음 뭐 해?”라고 물으면 이 프로젝트의 첫 미완료 과제·구체적인 첫 행동·완료 기준을 안내함. 다른 프로젝트의 과제도 질문하면 상대 저장소의 최신 계획을 확인함.
3. 완료 시 아래 표에 수행 주체·환경·대상 커밋·실행 근거·검증 결과를 기록하고 현재 단계와 다음 할 일을 갱신함. 비밀값·개인 데이터는 기록하지 않음.
4. 사용자 직접 실습은 사용자가 실행한 결과로 판단함. 에이전트 자기 검증·독립 검토·CI·로컬 적용·운영 적용은 별도 증거로 구분함.
